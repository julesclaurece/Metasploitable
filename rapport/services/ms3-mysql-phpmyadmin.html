MySQL / phpMyAdmin — Identifiants faibles

Mot de passe root vide confirmé, mais accès bloqué par deux protections indépendantes : ACL réseau MySQL et AllowNoPassword phpMyAdmin

3. Modules Metasploit — aucun applicable

search phpmyadmin remonte plusieurs modules RCE, mais tous inapplicables : phpmyadmin_preg_replace et phpmyadmin_null_termination_exec sont authentifiés (barrière de la section 2) ; le seul module non authentifié (phpmyadmin_config, CVE-2009-1151) ne couvre que phpMyAdmin ≤ 3.1.3.1, très antérieur à notre version 3.5.8.

4. Conclusion

Identifiants faibles confirmés (root sans mot de passe) — une vraie faiblesse de configuration. Mais deux protections indépendantes empêchent l'exploitation par les deux chemins testés. Contrairement à Samba et Drupal (bloqués par une seule cause), c'est ici un exemple de défense en profondeur qui fonctionne malgré une cause racine toujours présente.

5. Remédiation

RECOMMANDATIONS
  • Définir un mot de passe fort pour le compte root MySQL — les protections actuelles sont des filets de sécurité, pas un substitut à un vrai mot de passe.
  • Conserver l'ACL réseau MySQL restrictive et le réglage AllowNoPassword = false de phpMyAdmin — déjà efficaces, à documenter pour ne pas les désactiver par erreur.
  • Mettre à jour phpMyAdmin au-delà de 3.5.8 — reste vulnérable à plusieurs CVE authentifiées si un compte valide est compromis par ailleurs.
