Samba 3.0.20 — Énumération sans authentification

Partages et 35 comptes système récupérés via session SMB anonyme et RID cycling, avant toute tentative d'exploitation

Service / PortSMB (Samba) — ports 139 / 445
CibleMetasploitable 1 — 192.168.56.102
CVE— (énumération, pas d'exploitation sur cette page)
Résultat35 comptes système + 2 partages disque, sans authentification
Testé parZANNOU Josaphat
Note réseau. Cette page utilise le réseau de Josaphat (vboxnet0) : cible 192.168.56.102. Côté Jules, le même service est sur 172.28.128.4. Étape volontairement séparée de l'exploitation (samba-exploit.html) : l'énumération est une compétence à part entière, à faire avant de chercher à exploiter quoi que ce soit.

1. Identification

Reconnaissance du service et de sa version exacte.

$ nmap -sC -sV -p 139,445 192.168.56.102
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X (workgroup: WORKGROUP)
445/tcp open  netbios-ssn Samba smbd 3.0.20-Debian (workgroup: WORKGROUP)
Host script results:
| smb-os-discovery:
|   OS: Unix (Samba 3.0.20-Debian)
|   Computer name: metasploitable
smb-security-mode:
  account_used: guest
  message_signing: disabled (dangerous, but default)

Samba 3.0.20-Debian confirmé. Le script NSE a pu se connecter en tant que guest tout seul — premier signal que l'accès anonyme est permis.

2. Méthode d'énumération

Pas de CVE sur cette page — l'objectif est l'énumération, pas l'exploitation d'une faille précise. Première étape : lister les partages sans authentification.

$ smbclient -L //192.168.56.102/ -N
Anonymous login successful

	Sharename       Type      Comment
	---------       ----      -------
	print$          Disk      Printer Drivers
	tmp             Disk      oh noes!
	opt             Disk
	IPC$            IPC       IPC Service (metasploitable server (Samba 3.0.20-Debian))
	ADMIN$          IPC       IPC Service (metasploitable server (Samba 3.0.20-Debian))

-N = pas de mot de passe demandé. Anonymous login successful : le serveur accepte les connexions sans identifiants (null session). Deux partages disque exposés : tmp et opt.

Mécanisme du RID cycling. Une session SMB null (sans identifiants) suffit, sur cette version de Samba mal configurée, à interroger le SID du système (S-1-5-21-...) puis à énumérer séquentiellement les RID connus (500-550, 1000-1050 par défaut dans enum4linux) pour retrouver le nom de compte associé à chaque RID existant — sans jamais fournir de mot de passe. 
$ enum4linux -a 192.168.56.102
user:[root] rid:[0x3e8]
user:[msfadmin] rid:[0xbb8]
user:[user] rid:[0xbba]
user:[service] rid:[0xbbc]
user:[www-data] rid:[0x42a]
user:[tomcat55] rid:[0x4c4]
user:[postgres] rid:[0x4c0]
...
(35 comptes au total)

35 comptes système listés, dont les comptes applicatifs déjà croisés sur d'autres services (tomcat55, postgres, mysql, proftpd...) et les comptes utilisateurs du labo (msfadmin, user, service — les trois logins documentés dans parcours.md).

3. Démarche d'exploitation

Cette page couvre uniquement l'énumération. Cette liste de comptes valides est la base directe de l'exploitation (samba-exploit.html, CVE-2007-2447) : connaître msfadmin/root/service comme comptes réellement présents confirme que la cible a bien les comptes attendus du labo, avant de passer à l'attaque proprement dite.

4. Preuve d'accès obtenu

« Accès » ici signifie : lecture de métadonnées système (partages, comptes) sans aucune authentification valide — pas de shell à ce stade (voir samba-exploit.html pour l'accès root complet).

5. Remédiation

RECOMMANDATIONS
  • Désactiver l'accès anonyme/null session sur Samba (restrict anonymous = 2 et map to guest = never dans smb.conf), au minimum interdire l'énumération de comptes sans authentification.
  • Restreindre les partages exposés (tmp, opt) à des utilisateurs authentifiés et au principe de moindre privilège.
  • Mettre à jour Samba : 3.0.20 est très ancien et vulnérable (voir samba-exploit.html).
