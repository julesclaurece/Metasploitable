Samba — Énumération sans authentification

Partages, comptes système et politique de mot de passe récupérés via session SMB anonyme, avant toute tentative d'exploitation

Service / PortSMB (Samba) — ports 139 / 445
CibleMetasploitable 3 — 172.28.128.3
CVE— (énumération, pas d'exploitation sur cette page)
Résultat2 comptes système + 3 partages + politique de mot de passe, sans authentification
Testé parKAGBAHINTO Jules

1. Identification

Le scan de reconnaissance identifie un Samba smbd 3.X–4.X (workgroup WORKGROUP) sur les ports 139 et 445. Version imprécise à ce stade — l'objectif de cette page n'est pas de l'affiner mais de voir ce que le service révèle sans authentification.

2. Méthode d'énumération

Pas de CVE sur cette page — l'objectif est l'énumération, pas l'exploitation d'une faille précise. Première étape : lister les partages sans authentification (smbclient -L //172.28.128.3/ -N, capture a). Trois partages exposés : print$, public et IPC$ — ce dernier révèle au passage le hostname exact du serveur (metasploitable3-ub1404) dans son commentaire.

Tentative de lecture du partage public (son commentaire "WWW" suggère un lien avec le service web) : tree connect failed: NT_STATUS_ACCESS_DENIED — visible dans la liste, mais pas accessible en anonyme.

Mécanisme. La session SMB null (utilisateur et mot de passe vides) est acceptée par le serveur pour les opérations de listing — une mauvaise configuration courante, pas une faille de code. C'est cette même session anonyme qui permet ensuite l'énumération RID (comptes) ci-dessous, sans jamais fournir de mot de passe.

enum4linux -a 172.28.128.3 confirme la session null (Server ... allows sessions using username '', password '') et remonte deux comptes système : nobody et chewbacca (RID 1000 — premier compte "humain" après les comptes système par défaut, probablement ajouté intentionnellement pour ce labo). La politique de mot de passe est également récupérable sans authentification : complexité désactivée, longueur minimale de 5 caractères (capture b).

3. Démarche d'exploitation

Cette page couvre uniquement l'énumération. Le compte chewbacca et la politique de mot de passe faible (5 caractères, pas de complexité requise) donnent une piste de bruteforce réaliste pour une étape ultérieure — pas de CVE à exploiter ici, juste une mauvaise configuration à exploiter par la suite.

4. Preuve d'accès obtenu

« Accès » ici signifie : lecture de métadonnées système (partages, comptes, politique de mot de passe) sans aucune authentification valide — pas de shell à ce stade.

5. Remédiation

RECOMMANDATIONS
  • Désactiver l'accès anonyme/null session sur Samba (restrict anonymous = 2 et map to guest = never dans smb.conf).
  • Restreindre le partage public et masquer IPC$ du listing anonyme — le commentaire du service ne devrait pas exposer le hostname interne.
  • Renforcer la politique de mot de passe (longueur minimale et complexité) — 5 caractères sans complexité est bruteforçable en un temps raisonnable.
