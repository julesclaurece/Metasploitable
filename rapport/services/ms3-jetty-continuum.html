Apache Continuum — Arbitrary Command Execution

Exécution de commande arbitraire via un serveur d'intégration continue tournant avec les droits root

Service / PortHTTP (Jetty, Apache Continuum 1.4.2) — port 8080
CibleMetasploitable 3 — 172.28.128.3
CVECVE-2016-15057
RésultatAccès root (session Meterpreter complète)
Testé parKAGBAHINTO Jules

1. Identification

La racine du serveur Jetty renvoie une 404 sans rien révéler, et un gobuster générique ne trouve rien. Astuce qui a débloqué la recherche : Jetty liste lui-même ses contextes connus dans le corps de sa page d'erreur 404 — pas besoin de deviner à l'aveugle (capture a).

2. Méthode d'identification de la CVE et du module

searchsploit continuum puis search continuum dans msfconsole trouvent exploit/linux/http/apache_continuum_cmd_exec. info confirme CVE-2016-15057 (capture b).

Mécanisme. Une fonctionnalité de configuration des outils de build dans Continuum permet d'injecter des commandes système, exécutées par le serveur lors d'une build, sans validation suffisante des entrées — exécution de commande arbitraire avec les droits du processus Continuum.

3. Démarche d'exploitation

Exploitation directe via msfconsole, sans obstacle rencontré — contrairement à Samba et Drupal sur cette même cible (capture c).

4. Preuve d'accès obtenu

sessions -i 1 -c id confirme root direct — pas une élévation en deux temps, le processus Continuum tournait déjà en root sur cette install (capture d).

5. Remédiation

RECOMMANDATIONS
  • Mettre à jour Apache Continuum au-delà de 1.4.2, ou migrer vers un outil de CI maintenu (Continuum est un projet Apache retiré depuis plusieurs années).
  • Ne jamais faire tourner un serveur de build/CI avec les droits root — c'est la cause de gravité de cette CVE, pas juste la faille elle-même.
  • Restreindre l'accès réseau à l'interface Continuum (VPN, pare-feu, authentification) — elle n'a aucune raison d'être exposée publiquement.
