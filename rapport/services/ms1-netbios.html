NetBIOS Name Service

Reconnaissance du nom de machine et du domaine avant toute énumération SMB

Service / PortNetBIOS Name Service — port 137/udp
CibleMetasploitable 1 — 192.168.56.102
CVE— (reconnaissance, pas d'exploitation)
RésultatNom de machine et domaine révélés sans toucher SMB
Testé parZANNOU Josaphat
Note réseau. Cette page utilise le réseau de Josaphat (vboxnet0) : cible 192.168.56.102. Côté Jules, le même service est sur 172.28.128.4. Étape volontairement rapide : montrer qu'on peut récupérer des informations utiles avant d'entamer l'énumération SMB elle-même (samba-enum.html).

1. Identification

Interrogation NetBIOS directe, sans passer par SMB.

$ nmblookup -A 192.168.56.102
Looking up status of 192.168.56.102
	METASPLOITABLE  <00> -         B 
	METASPLOITABLE  <03> -         B 
	METASPLOITABLE  <20> -         B 
	..__MSBROWSE__. <01> -  B 
	WORKGROUP       <00> -  B 
	WORKGROUP       <1d> -         B 
	WORKGROUP       <1e> -  B

2. Méthode de lecture des codes de service

Pas de CVE ici : chaque entrée associe un nom à un code de suffixe (2 chiffres hex) qui indique le type de service NetBIOS enregistré sous ce nom.

METASPLOITABLE<00>Workstation Service — nom de la machine
METASPLOITABLE<03>Messenger Service
METASPLOITABLE<20>File Server Service — le partage SMB est actif
WORKGROUP<00>Nom du groupe de travail
WORKGROUP<1d>Local Master Browser
WORKGROUP<1e>Browser Election Service

Sans avoir touché SMB, on sait déjà : le nom de machine (METASPLOITABLE), le domaine (WORKGROUP), et que le service de partage de fichiers est actif (<20>) — confirmé ensuite en détail dans samba-enum.html.

3. Démarche d'exploitation

Aucune exploitation sur cette page : le nom de machine et le domaine récupérés ici servent de base pour construire une wordlist de noms d'hôtes/domaines pour une attaque ultérieure (ex. formats d'authentification SMB du type DOMAINE\utilisateur), même si dans ce labo l'énumération d'utilisateurs se fait plus efficacement via RID cycling (samba-enum.html).

4. Preuve d'accès obtenu

Pas de shell ici — résultat de reconnaissance pure (nom de machine + domaine).

5. Remédiation

RECOMMANDATIONS
  • Désactiver NetBIOS (port 137/udp) si le partage de fichiers Windows/SMB legacy n'est pas nécessaire, ou le restreindre au réseau interne uniquement (pare-feu).
  • Ne pas exposer de nom de machine ou de domaine interne sur un réseau non maîtrisé : cette information facilite la reconnaissance (wordlists, social engineering).
