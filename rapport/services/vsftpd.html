vsftpd 2.3.4 — Backdoor

Exécution de commande à distance via porte dérobée insérée dans la chaîne de distribution

Service / PortFTP (vsftpd) — port 21
CibleMetasploitable 2 — 172.28.128.5
CVECVE-2011-2523
RésultatAccès root (session Meterpreter complète)
Testé parKAGBAHINTO Jules

1. Identification

Le scan de reconnaissance sur le port 21 de la cible révèle un serveur FTP vsftpd en version 2.3.4 — une version précise connue pour avoir été compromise au niveau de sa distribution officielle.

2. Méthode d'identification de la CVE et du module

À partir de la version exacte obtenue en reconnaissance (vsftpd 2.3.4), première question indépendante de tout outil : cette version a-t-elle une faille connue ? searchsploit vsftpd 2.3.4 confirme qu'un exploit existe, mais ne donne ni CVE ni chemin de module Metasploit directement utilisable (capture b ci-dessous).

Étape suivante : chercher dans msfconsole puisque c'est l'outil choisi pour l'exploitation — search vsftpd donne deux résultats, mais un seul correspond à la version 2.3.4 précise identifiée en reconnaissance (vsftpd_232 vise une version antérieure, un simple déni de service). C'est de là que vient le chemin exact exploit/unix/ftp/vsftpd_234_backdoor (même capture b).

Reste à obtenir la CVE elle-même, absente des deux résultats précédents : info sur le module donne, dans sa section References, CVE-2011-2523 (capture c). En recoupant avec les liens fournis, on comprend la nature exacte de la faille : entre le 30 juin et le 3 juillet 2011, l'archive source officielle de vsftpd 2.3.4 a été remplacée par une version trafiquée directement sur le serveur de téléchargement du mainteneur — une compromission de la chaîne de distribution logicielle (supply chain), et non une faille de conception dans le code légitime du projet. Le code injecté active un mécanisme simple : si le nom d'utilisateur envoyé lors d'une connexion FTP contient la séquence :), le serveur ouvre un shell root en écoute sur le port TCP 6200, sans authentification supplémentaire.

Backdoor déclenchée par un simple login FTP contenant :) — aucune authentification valide requise. Shell root ouvert en écoute sur 6200/tcp.

3. Démarche d'exploitation

Le module Metasploit dédié existant déjà (exploit/unix/ftp/vsftpd_234_backdoor), aucune recherche d'exploit supplémentaire n'était nécessaire. Démarche interactive dans msfconsole, commande par commande : use du module puis set RHOSTS / set RPORT / set LHOST (capture d). Point d'attention — LHOST est obligatoire ici car le payload par défaut du module est un reverse Meterpreter, qui doit savoir où rappeler.

Une fois la configuration validée, exploit -z déclenche l'attaque (le -z bascule la session en arrière-plan dès son ouverture, sans y entrer automatiquement).

4. Preuve d'accès obtenu

La commande sessions -i 1 -c id exécute id directement dans la session ouverte, sans y entrer en mode interactif.

5. Remédiation

RECOMMANDATIONS
  • Mettre à jour vsftpd vers une version ultérieure non affectée par cette compromission historique (toute version postérieure à juillet 2011).
  • Vérifier systématiquement l'intégrité des archives source téléchargées (hash SHA-256 publié par le mainteneur) avant compilation/déploiement, en particulier pour les logiciels critiques exposés sur Internet.
  • Mettre en place une surveillance réseau capable de détecter l'ouverture inhabituelle d'un port en écoute (ici 6200/tcp) consécutive à une connexion sur un service exposé.
  • Appliquer le principe de moindre privilège : un service FTP ne devrait jamais pouvoir, même en cas de compromission, ouvrir un shell avec des droits root.
